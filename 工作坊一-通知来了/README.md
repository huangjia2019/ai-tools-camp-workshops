# 工作坊一：通知来了 · 谁是卧底

## 背景

6 月 30 日，星期二，下午四点半，交易所发布了参数调整通知，原文在[资料包](资料包.md)里。部门有个内部小工具《涨跌停与保证金试算》，业务、风控、客服每天用它查当天参数、试算保证金。7 月 2 日之前，要把它改成按新通知算对的加强版。

这个小工具是组里三位系统工程师写的，可三个人的说法不一样。信谁，要看资料。

## 每组一道题

| 组 | 题目 |
| --- | --- |
| 一组 | 7 月 2 日（星期四）晚上 21:30，有人下了一笔 CU2608 的委托。按新通知，这笔委托的涨停价是多少？ |
| 二组 | 7 月 2 日收盘结算时，某客户持有 CU2608 一般持仓 4 手。这一次结算，交易保证金是多少？ |
| 三组 | 7 月 3 日收盘结算时，某客户持有 CU2607 一般持仓 2 手。这一次结算，交易保证金是多少？ |

13:30 用你们的加强版把本组那道题算出来。

## 需求单

产品经理拍板，每一条写依据：资料包第几条，还是谁说的。找不到依据的，写进“待确认”。

```
1. 加入 6 月 30 日的通知：哪些合约、哪些参数、生效日：________（依据：________）
2. 交易日怎么算：要不要看委托时间：________（依据：________）
3. 结算当天用新比例还是旧比例：________（依据：________）
4. 一般持仓保证金：通知比例和阶段标准怎么取：________（依据：________）
5. 还有哪些待确认：________（依据：________）
```

## 给 TRAE 的提示词

把初始版 HTML 和资料包一起交给 TRAE，贴上这段提示词，再把需求单贴在最后。

```
这是我们部门的内部小工具《涨跌停与保证金试算》v1.0（附件 HTML 文件）。
交易所 6 月 30 日发了参数调整通知，通知原文和相关规则在附件《资料包》里。
请按下面的需求单把它改成 v2.0：
1. 只改需求单里写了的地方，其他保持不变；
2. 每处改动在代码注释里写依据：资料包里哪份文件第几条，或者需求单第几条；
3. 价格和金额继续用整数计算，不用浮点数；
4. 改完列出改了哪几处；需求单里写得不清楚的地方，列出来问我们，不要自己决定。

【需求单】
1. ……（依据：……）
2. ……（依据：……）
```
