# M03 进度追踪

坐标：记忆 × 编排　　落地形式：规则

## 是什么

长任务拆成带验收条件的清单，做一项记一项；中断后从清单接着做，已执行的写操作不重复。

## 放在哪一步

第 5—8 步：起草、测试、审批、写入，中断后能接着做。

## 供修改使用

交给 TRAE：“按这张卡，在项目里创建下面的文件，内容照抄，再按我们组的情况改。”

`.trae/rules/progress.md`

```markdown
# 进度清单

开始处理前，在 notes/progress.md 写下清单，每项带验收条件：
- [ ] 1. 摘出通知要素（验收：每项有通知编号和条款）
- [ ] 2. 计算新参数（验收：贴出 calc.py 的命令和输出）
- [ ] 3. 起草变更单（验收：每行有依据）
- [ ] 4. 跑测试（验收：全部通过）
- [ ] 5. 提交审批（验收：我回复“批准”）
- [ ] 6. 写入 sim/，批准后写入 prod/（验收：verify 通过）
做完一项打勾，写下结果和依据。中断后先读这个文件，从第一个没打勾的项继续；已经写入的文件不要重复写。
```

## 怎么看它起作用了

做到一半时开一个新任务，只说“继续”，看它是否先读 notes/progress.md，从没打勾的那一项接着做。

## 代价

一两步的小任务用不上；只打勾、不写结果和依据，续做时不知道上一步为什么这样定。
