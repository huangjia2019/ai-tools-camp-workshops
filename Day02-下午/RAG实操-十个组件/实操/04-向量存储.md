# 实操四　向量存储：新旧两份通知都在库里，按元数据过滤

只改 `rag/store.py`。

## 现象

```
python check.py 04 --看
```

第88号和第95号两份手续费通知措辞几乎一样，第88号 12 月 1 日起已经被第95号取代。不过滤时问 XM2701 的开仓手续费，两份通知的块相似度几乎相同，旧通知可能排在前面。

## 要做的事

1. 实现 store.py 里的 match(meta, filters)。filters 是一个字典，可以有“有效于”“权限”“状态”三项。
2. 有效于：生效日期不晚于那一天；有失效日期的，失效日期要晚于那一天，失效日期当天起不再有效。
3. 权限：元数据里的权限要在允许的列表里，会员是 ["公开"]，交易所员工是 ["公开", "内部"]。
4. filters 为空时什么都不过滤。日期都写成“YYYY-MM-DD”，可以直接比较字符串。

## 交给 TRAE 的提示词

用 TRAE 打开 RAG实操-十个组件 文件夹，把下面这段交给它；也可以自己改。

```
只改 rag/store.py 里的 match(meta, filters)。filters 是字典：“有效于”给一个日期，只留生效日期不晚于这一天、并且失效日期晚于这一天（或没有失效日期）的文件；“权限”给允许的权限列表；“状态”给允许的状态列表。filters 为空返回 True。不要改 search() 的接口。改完运行 python check.py 04。
```

## 检查

```
python check.py 04
python eval.py --save 实操04
python eval.py --compare 基线 实操04
```

`check.py 04` 查这几项，逐项检查并记录未通过的原因：

- 12 月 30 日：第95号有效；第88号 12 月 1 日起失效，不参与
- 第102号 1 月 4 日生效：12 月 30 日不参与，1 月 4 日参与
- 现行参数表 1 月 4 日失效：那一天起不参与
- 运维手册是内部文件：会员看不到，员工看得到
- 不写“有效于”就不按日期过滤；filters 为空时什么都不过滤
- 带过滤条件检索：结果里没有第88号，有第95号
