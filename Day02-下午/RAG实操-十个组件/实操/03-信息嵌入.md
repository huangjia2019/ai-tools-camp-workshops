# 实操三　信息嵌入：合约代码只差一个字符，加一个关键词通道

只改 `rag/embed.py`。

## 现象

```
python check.py 03 --看
```

练习系统用字符二元组充当向量。XM2701、XM2702、XM2703 只差最后一位，问 XM2703 的手续费时，另外两个合约那一行的相似度只比它低 0.07 左右。换成密集向量模型，也会遇到同样的问题。

## 要做的事

1. 在 embed.py 的 grams() 里，除了二元组，再把文字里的合约代码当作一个完整的词加进去，例如“#XM2703”，重复几次加大权重。
2. 合约代码用 rag/utils.py 里现成的 contract_codes() 找。
3. fit() 和 encode() 两个接口不变，向量仍然归一化。

## 交给 TRAE 的提示词

用 TRAE 打开 RAG实操-十个组件 文件夹，把下面这段交给它；也可以自己改。

```
只改 rag/embed.py。在 grams() 里，除了字符二元组，再把文字里的合约代码（用 utils.contract_codes 找）作为一个完整的词加进去，重复 3 次加大权重。fit 和 encode 的接口不变。改完运行 python check.py 03 --看，再运行 python check.py 03。
```

## 检查

```
python check.py 03
python eval.py --save 实操03
python eval.py --compare 基线 实操03
```

`check.py 03` 查这几项，逐项检查并记录未通过的原因：

- 问“XM2702 平今多少钱一手？”：XM2702 那一行比另外两行至少高 0.2
- 问“XM2703 合约平今仓的手续费是多少？”：XM2703 那一行至少高 0.2
- 问“XM2701 的开仓手续费是多少？”：XM2701 那一行至少高 0.2
- 向量仍然是单位长度：一段文字和自己的相似度是 1
