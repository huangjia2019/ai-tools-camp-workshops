# 实操六　索引优化：每份文件一个摘要节点，元数据写成能检索的文字

只改 `rag/index.py`。

## 现象

```
python check.py 06 --看
```

第103号更正通知的正文里没写哪天生效，生效日期只在元数据里；第61号、第88号的正文里也没有“失效”两个字。问“哪些通知从 1 月 4 日起生效”“哪些通知已经失效了”，正文块答不上来。

## 要做的事

1. 在 index.py 的 build_index() 里，给每份文件加一个摘要节点：id 写成“编号#摘要”，doc、meta 和这份文件相同，再加一个键 "kind": "摘要"。
2. 摘要的文字写编号、标题、类型、涉及的合约、生效和失效时点、状态，以及取代、更正关系，例如：第102号　关于调整……的通知｜类型 通知｜涉及合约 XM2701、XM2702、XM2703｜2027 年 1 月 4 日起生效｜状态 现行｜被第103号更正
3. 日期写成“2027 年 1 月 4 日”，和问题里的说法对得上。
4. 原来的块全部保留。检索到摘要节点以后怎么用，expand() 已经写好：摘要用来找到文件，回答仍然引用正文。

## 交给 TRAE 的提示词

用 TRAE 打开 RAG实操-十个组件 文件夹，把下面这段交给它；也可以自己改。

```
只改 rag/index.py 里的 build_index(chunks, docs)：原来的块全部保留，再给每份文件加一个摘要节点，键有 id（编号#摘要）、doc、text、meta、kind（值为“摘要”）。text 写编号、标题、类型、涉及的合约（utils.contract_codes）、生效和失效日期（写成“2027 年 1 月 4 日起生效”）、状态，以及取代、被取代、更正、被更正关系，用“｜”隔开。不要改 expand()。改完运行 python check.py 06。
```

## 检查

```
python check.py 06
python eval.py --save 实操06
python eval.py --compare 基线 实操06
```

`check.py 06` 查这几项，逐项检查并记录未通过的原因：

- 每份文件一个摘要节点
- 原来的块一块不少
- 第102号的摘要写了编号、合约、“1 月 4 日”生效、状态和更正关系
- 问“哪些通知从 1 月 4 日起生效？”：前五块里有第103号
- 问“哪些通知已经失效了？”：前五块里有第61号和第88号
