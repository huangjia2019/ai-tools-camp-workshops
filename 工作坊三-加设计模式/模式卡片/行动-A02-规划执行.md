# A02 规划执行

坐标：行动 × 编排　　落地形式：规则

## 是什么

先出包含依赖和审批点的计划，确认后按计划执行；遇到新情况，只改受影响的部分。

## 放在哪一步

第 1—8 步：处理整批通知前先出计划。

## 照抄就能用

交给 TRAE：“按这张卡，在项目里创建下面的文件，内容照抄，再按我们组的情况改。”

`.trae/rules/plan.md`

```markdown
# 先出计划

处理通知前，先在 notes/plan.md 写计划，不要直接动手：
- 处理哪几份通知，先后顺序和理由（更正通知要和原通知一起看）
- 每一步做什么、用哪个工具、产出什么文件
- 哪一步要我确认
写完停下，等我回复“开始”。执行中发现新情况，例如通知和数据对不上，先改计划里受影响的部分，再继续。
```

## 怎么看它起作用了

说“处理 inbox 里的全部通知”，看它是否先交 notes/plan.md 并停下；执行中遇到新情况时，计划是否被更新。也可以在 TRAE 里输入 / 选 Plan。

## 代价

步骤固定的例行任务每次重新规划是浪费，用提示链；计划写了没人看就执行，等于没有计划。
