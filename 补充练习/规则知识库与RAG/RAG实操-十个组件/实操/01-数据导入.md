# 实操一　数据导入：附表逐行写成句子，表头和单位跟着每一行走

只改 `rag/load.py`。

## 现象

```
python check.py 01 --看
```

第95号通知的附表读进来还是 Markdown 表格。基础版每 80 个字切一块，“| XM2703 | 1 | 4 | 1 |”这一行和表头落在不同的块里，块里只剩一串数字，看不出哪个数是平今仓手续费，也看不出单位。问“XM2703 合约平今仓的手续费是多少”，答不对。

## 要做的事

1. 在 load.py 里把正文中的 Markdown 表格改写成句子，每个数据行写成一句，例如：合约 XM2703：开仓手续费 1 元/手，平今仓手续费 4 元/手，平昨仓手续费 1 元/手。
2. 单位从表头的括号里取：“开仓手续费（元/手）”拆成名称“开仓手续费”和单位“元/手”，单位写在数值后面。
3. 四个带表格的文件都要处理：第88号、第95号、现行参数表、技术服务收费标准。每句单独成一段，前后各空一行。
4. 元数据不动。

## 操作要求

Qoder CN：先在智能问答模式分析目标文件与失败用例，确认后切到智能体模式修改。

TRAE：引用目标文件与用例，先分析，再按确认的范围修改。两款工具都把下面这段提示词交给 AI，改完在项目终端运行“检查”里的命令。

```
只改 rag/load.py。把正文里的 Markdown 表格改写成句子：每个数据行写成一句，格式是“第一列的列名 第一列的值：其余每列的列名 值 单位，……。”，单位从列名的括号里取出来，写在数值后面；每句单独成一段。不要为某一份文件写特例，不要改别的文件。改完运行 python check.py 01。
```

## 检查

```

python eval.py --save 实操01
python eval.py --compare 基线 实操01
```

`check.py 01` 查这几项，逐项检查并记录未通过的原因：

- 第95号附表：XM2703 那一行写成一句，带着“平今仓手续费”和“4 元/手”
- 收费标准表：托管机柜那一行带着“8000 元/月”
- 现行参数表：XM2702 那一行带着列名和“8%”
- 所有文件里不再有“|”开头的表格行
- 元数据还在：每份文件都有编号和生效日期
