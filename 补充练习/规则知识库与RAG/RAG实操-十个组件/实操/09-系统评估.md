# 实操九　系统评估：对比两次结果时，按题型分开看

只改 `eval.py`。

## 现象

```
python check.py 09 --看
```

eval.py --compare 只告诉你总分和哪几道题变了。总分涨了，某一类题可能同时退步，比如改了分块以后召回率上升，时点题反而错了，总分把这种退步盖住了。

## 要做的事

1. 在 eval.py 里加一个函数 compare_by_type(ra, rb)：输入两次存下的结果，返回 {题型: (前一次通过几道, 后一次通过几道, 这类题共几道)}。
2. 在 compare() 的最后，按题型逐行打印，例如“时点　2/2 → 1/2”；后一次比前一次少的那一行末尾标“退步”，多的标“进步”。
3. 不改 judge() 的判分规则。

## 操作要求

Qoder CN：先在智能问答模式分析目标文件与失败用例，确认后切到智能体模式修改。

TRAE：引用目标文件与用例，先分析，再按确认的范围修改。两款工具都把下面这段提示词交给 AI，改完在项目终端运行“检查”里的命令。

```
只改 eval.py。新增 compare_by_type(ra, rb)，按题型统计两次结果各通过几道，返回 {题型: (前一次通过数, 后一次通过数, 题数)}；在 compare() 末尾按题型逐行打印“题型　前/题数 → 后/题数”，后一次少了标“退步”，多了标“进步”。不要改 judge() 和别的函数的判分逻辑。改完运行 python check.py 09，再用 python eval.py --compare 基线 实操08 看看。
```

## 检查

```
python check.py 09
python eval.py --save 实操09
python eval.py --compare 基线 实操09
```

`check.py 09` 查这几项，逐项检查并记录未通过的原因：

- compare_by_type 按题型数对：时点 2 → 1，表格 0 → 2，拒答 1 → 1
- --compare 按题型列出变化，退步的那一类标“退步”
