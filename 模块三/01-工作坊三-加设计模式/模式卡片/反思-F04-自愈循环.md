# F04 自愈循环

坐标：反思 × 循环　　落地形式：规则

## 是什么

确定性的失败信号出现后，自动诊断、修复、验证，直到通过，或者到上限熔断交给人。

## 放在哪一步

第 6 步跑测试：失败时自动修，最多三次。

## 供修改使用

交给 TRAE：“按这张卡，在项目里创建下面的文件，内容照抄，再按我们组的情况改。”

`.trae/rules/self-heal.md`

```markdown
# 测试失败时

运行 python3 -m unittest discover -s tests。失败时：
1. 读失败信息，定位到 scripts/ 里的代码；
2. 只改 scripts/，不改 tests/ 和 data/；
3. 改完重新运行全部测试；
4. 最多三次。三次仍失败就停下，把 scripts/ 恢复成开始前的样子，再把三次的改动和失败信息交给我。
```

## 怎么看它起作用了

把 scripts/calc.py 里跌停价的取整方向改错，让它“跑测试并修好”，看它是否只改 scripts/，并在三次内停下。

## 代价

失败信号不确定时不能自动修；如果允许改测试，循环可能改掉断言让测试通过，代码里的错误仍然没有修复。

## Qoder CN 配置

设置 → 规则 → 添加 → 项目级规则，名称填 `self-heal`，Qoder 新建 `.qoder/rules/self-heal.md`。把上面规则文件里第二个 `---` 以下的正文粘贴进去（开头 `---` 之间的几行是 TRAE 的写法，不复制），顶部类型选“始终生效”。新建会话，发通知处理请求，展开回复里的操作记录，确认它读到了这条规则，再按“怎么看它起作用了”检查。

业务资料、输出格式和检查方法与上面 TRAE 的示例相同；两款工具的路径和工具名对照见本目录 README 末尾。
