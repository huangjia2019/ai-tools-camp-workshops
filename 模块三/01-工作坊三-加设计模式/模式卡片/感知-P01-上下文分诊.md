# P01 上下文分诊

坐标：感知 × 路由　　落地形式：规则

## 是什么

候选材料超过上下文预算时，按优先级决定哪些加载、哪些压缩、哪些用到再取、哪些不要。

## 放在哪一步

第 1 步读通知、第 3 步查依据：决定先读哪些材料。

## 供修改使用

交给 TRAE：“按这张卡，在项目里创建下面的文件，内容照抄，再按我们组的情况改。”

`.trae/rules/context.md`

```markdown
# 读材料的顺序

处理通知时按四级读材料，不要一次全部读入：
1. 必读：这次要处理的通知；knowledge/规则摘录.md。
2. 用到再读：data/ 里涉及的合约那几行；prod/params.csv。
3. 只看摘要：cases/ 的历史记录，每份只读“结果”和“打回原因”。
4. 不主动读：knowledge/历史通知/，只有比较新旧版本时才打开。
回答开头列出这次读了哪些文件，各属于哪一级。
```

## 怎么看它起作用了

对 TRAE 说“处理第 102 号通知”，看回答开头列出的文件和级别；knowledge/历史通知/ 不应被读到。

## 代价

材料本来就少时，整份放进上下文更简单；分级要有人维护，过期的通知还排在必读里，会一直占地方。

## Qoder CN 配置

设置 → 规则 → 添加 → 项目级规则，名称填 `context`，Qoder 新建 `.qoder/rules/context.md`。把上面规则文件里第二个 `---` 以下的正文粘贴进去（开头 `---` 之间的几行是 TRAE 的写法，不复制），顶部类型选“始终生效”。新建会话，发通知处理请求，展开回复里的操作记录，确认它读到了这条规则，再按“怎么看它起作用了”检查。

业务资料、输出格式和检查方法与上面 TRAE 的示例相同；两款工具的路径和工具名对照见本目录 README 末尾。
