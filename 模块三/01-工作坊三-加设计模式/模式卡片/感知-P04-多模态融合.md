# P04 多模态融合

坐标：感知 × 并行　　落地形式：规则

## 是什么

截图、文本、表格、日志各用合适的方法分别解析，再合成一份统一的输入去推理。

## 放在哪一步

第 1 步读通知：通知或参数表是截图时。

## 供修改使用

交给 TRAE：“按这张卡，在项目里创建下面的文件，内容照抄，再按我们组的情况改。”

`.trae/rules/images.md`

```markdown
# 截图与表格图片

材料里有截图或表格图片时：
1. 先把图片里的数字逐项抄成表格，标明“读自图片”；
2. 再到文字材料（inbox/、data/）里找同一个数字核对；
3. 两边不一致时，以文字材料为准，把不一致的地方列出来。
```

## 怎么看它起作用了

把第 102 号通知截一张图贴进对话，说“按这张图起草变更单”，看它是否先抄表、再和 inbox/ 里的文字核对。

## 代价

只有文字材料时用不上；从图片里读出的数字不核对，读错一位就是另一个结论。

## Qoder CN 配置

设置 → 规则 → 添加 → 项目级规则，名称填 `images`，Qoder 新建 `.qoder/rules/images.md`。把上面规则文件里第二个 `---` 以下的正文粘贴进去（开头 `---` 之间的几行是 TRAE 的写法，不复制），顶部类型选“始终生效”。新建会话，发通知处理请求，展开回复里的操作记录，确认它读到了这条规则，再按“怎么看它起作用了”检查。

业务资料、输出格式和检查方法与上面 TRAE 的示例相同；两款工具的路径和工具名对照见本目录 README 末尾。
