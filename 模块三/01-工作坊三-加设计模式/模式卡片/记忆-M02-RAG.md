# M02 RAG

坐标：记忆 × 链式　　落地形式：规则

## 是什么

先检索相关资料，再带着资料作答，写明出处、版本和生效时点。

## 放在哪一步

第 3 步查依据：每个数字都有出处，并且取现在有效的那份通知。

## 供修改使用

交给 TRAE：“按这张卡，在项目里创建下面的文件，内容照抄，再按我们组的情况改。”

`.trae/rules/cite.md`

```markdown
# 引用依据

回答参数问题时：
1. 先在 inbox/ 和 knowledge/ 里检索相关通知；
2. 同一事项有多份通知时，看起用日期和有没有更正，只取现在有效的那一份；
3. 每个数字后面写出处：文件名、第几条、起用日期；
4. 引用的句子和原文一致；找不到出处的写“未找到依据”。
knowledge/历史通知/ 里的通知已失效，只在比较新旧版本时引用。
```

## 怎么看它起作用了

问“XM2703 套期保值持仓的新保证金比例是多少”，看它是否以第 103 号更正通知为准，并写明条款。

## 代价

材料少时整份放进上下文即可；资料不写起用日期、不标是否被更正，检索得再准也会引到过期的通知。

## Qoder CN 配置

设置 → 规则 → 添加 → 项目级规则，名称填 `cite`，Qoder 新建 `.qoder/rules/cite.md`。把上面规则文件里第二个 `---` 以下的正文粘贴进去（开头 `---` 之间的几行是 TRAE 的写法，不复制），顶部类型选“始终生效”。新建会话，发通知处理请求，展开回复里的操作记录，确认它读到了这条规则，再按“怎么看它起作用了”检查。

业务资料、输出格式和检查方法与上面 TRAE 的示例相同；两款工具的路径和工具名对照见本目录 README 末尾。
