# F03 经验回放

坐标：反思 × 层级　　落地形式：规则

## 是什么

从历史执行记录、人工接管和事后结果里提取经验；新任务开始时，取回适用的部分。

## 放在哪一步

第 1 步之前：先看相似的历史处理记录。

## 供修改使用

交给 TRAE：“按这张卡，在项目里创建下面的文件，内容照抄，再按我们组的情况改。”

`.trae/rules/replay.md`

```markdown
# 先看历史记录

处理新通知前：
1. 在 cases/ 里找最相似的两份处理记录（同类通知、同样的参数）；
2. 列出它们的做法和打回原因；
3. 说明这次怎样避免同样的问题，再开始。
处理完成后，在 cases/ 新建一份记录：通知编号、做了什么、产出文件；结果和打回原因由我填写。
```

## 怎么看它起作用了

处理第 102 号通知前，看它是否先引用 cases/ 里被打回的那份记录，并说明这次怎样避免漏掉套期保值持仓。

## 代价

记录太少或规则刚改过时，旧记录会误导；只留通过的记录、不留打回原因，用处不大。

## Qoder CN 配置

设置 → 规则 → 添加 → 项目级规则，名称填 `replay`，Qoder 新建 `.qoder/rules/replay.md`。把上面规则文件的内容整段粘贴进去，顶部类型选“始终生效”。新建会话，发通知处理请求，展开回复里的操作记录，确认它读到了这条规则，再按“怎么看它起作用了”检查。

业务资料、输出格式和检查方法与上面 TRAE 的示例相同；两款工具的路径和工具名对照见本目录 README 末尾。
