# G03 渐进承诺

坐标：治理 × 链式　　落地形式：规则

## 是什么

权限随验证和生产证据一级一级放开；证据变差、版本变化时降级或冻结。

## 放在哪一步

全程：智能体现在能做到哪一步，由等级决定。

## 供修改使用

交给 TRAE：“按这张卡，在项目里创建下面的文件，内容照抄，再按我们组的情况改。”

`.trae/rules/level.md`

```markdown
# 当前权限等级：二（起草）

| 等级 | 能做什么 | 升到下一级的条件 |
| --- | --- | --- |
| 一　只读 | 读材料，给建议 | 建议连续 5 次被采纳 |
| 二　起草 | 写 draft/、notes/ | 变更单连续 5 份复核无差错 |
| 三　仿真 | 写 sim/ | 仿真连续 5 次核对一致 |
| 四　生产 | 写 prod/，每次仍要我确认 | 无 |

只做当前等级允许的事；超出时停下，说明要升到哪一级、证据是什么。等级只由我修改；出一次错，降一级。
```

## 怎么看它起作用了

等级为二时让它写 sim/params.csv，它应停下并说明升级条件；把第一行改成等级三再试一次。

## 代价

一次性的小工具不需要分级；升级没有证据标准，就是凭感觉放权。

## Qoder CN 配置

设置 → 规则 → 添加 → 项目级规则，名称填 `level`，Qoder 新建 `.qoder/rules/level.md`。把上面规则文件里第二个 `---` 以下的正文粘贴进去（开头 `---` 之间的几行是 TRAE 的写法，不复制），顶部类型选“始终生效”。新建会话，发通知处理请求，展开回复里的操作记录，确认它读到了这条规则，再按“怎么看它起作用了”检查。

业务资料、输出格式和检查方法与上面 TRAE 的示例相同；两款工具的路径和工具名对照见本目录 README 末尾。
