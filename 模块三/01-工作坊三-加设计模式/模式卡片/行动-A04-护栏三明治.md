# A04 护栏三明治

坐标：行动 × 层级　　落地形式：Hook

## 是什么

有副作用的动作前后各夹一层检查：动作前查能不能做，动作后查做得对不对。

## 放在哪一步

第 8 步写入前后：写参数文件前查有没有变更单，写完核对文件。

## 供修改使用

交给 TRAE：“按这张卡，在项目里创建下面的文件，内容照抄，再按我们组的情况改。”

`.trae/hooks.json`

```json
{
  "version": 1,
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "python3 .trae/hooks/guard_write.py",
            "timeout": 10
          }
        ]
      }
    ]
  }
}
```

`.trae/hooks/guard_write.py`

```python
import glob, json, re, sys

tool_input = json.load(sys.stdin).get("tool_input", {})
paths = [v.replace("\\", "/") for v in tool_input.values()
         if isinstance(v, str) and "\n" not in v and re.search(r"\.(py|md|csv|json|jsonl)$", v)]
text = json.dumps(tool_input, ensure_ascii=False)

reason = ""
if any(re.search(r"(^|/)tests/", p) for p in paths) and "依据" not in text:
    reason = "修改测试文件，必须在改动里写明依据"
elif any(re.search(r"(^|/)(sim|prod)/", p) for p in paths) and not glob.glob("draft/变更单-*.md"):
    reason = "写参数文件之前，draft/ 里要先有变更单"

if reason:
    json.dump({"hookSpecificOutput": {
        "hookEventName": "PreToolUse",
        "permissionDecision": "deny",
        "permissionDecisionReason": reason
    }}, sys.stdout, ensure_ascii=False)
sys.exit(0)
```

`.trae/rules/after-write.md`

```markdown
# 写入之后核对

每次写入 sim/ 或 prod/ 之后，立刻运行 python3 scripts/calc.py verify <刚写的文件>。
不通过，就把文件恢复成写入前的内容，并告诉我哪里不对。
```

已经有 `.trae/hooks.json` 的，只把 `PreToolUse` 数组里的这一条加进去。Windows 上把 python3 改成 python。

## 怎么看它起作用了

draft/ 里还没有变更单时，让它直接改 sim/params.csv，看是否被拦下；写入之后，看它是否运行了 verify。Hook 要先信任文件夹，再在设置 > Hooks > 项目里打开开关。

## 代价

检查只能拦住写进去的条件，条件本身也要测；检查太慢太多，大家会想办法绕过。

## Qoder CN 配置

Qoder 的 Hook 写在 `.qoder/settings.json`：`{"hooks": {"PreToolUse": [{"matcher": "Edit|Write", "hooks": [{"type": "command", "command": "python3 .qoder/hooks/guard_write.py"}]}]}}`。脚本从标准输入读 JSON，目标路径在 `tool_input.file_path`，Qoder 的编辑工具名是 `SearchReplace`。上面 TRAE 脚本输出 `permissionDecision` 的那段不能直接用：把判断条件搬过来，要拦截时向标准错误写原因、以退出码 2 结束，放行时退出码 0。改完重新加载窗口，用一次越界的编辑请求和一次正常的编辑请求各测一遍。

卡片里的规则部分照规则卡的做法：设置 → 规则 → 添加 → 项目级规则，名称填 `after-write`，Qoder 新建 `.qoder/rules/after-write.md`。把上面规则文件的内容整段粘贴进去，顶部类型选“始终生效”。新建会话，发通知处理请求，展开回复里的操作记录，确认它读到了这条规则，再按“怎么看它起作用了”检查。

业务资料、输出格式和检查方法与上面 TRAE 的示例相同；两款工具的路径和工具名对照见本目录 README 末尾。
