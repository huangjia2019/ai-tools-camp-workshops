# 模式卡片

七组 27 个矩阵模式，加上横切的可观测性，各一张卡。工作坊三里卡有两种用法：第二层拿来对照，认出 改动/ 里的文件是哪个模式，再按卡上“怎么看它起作用了”找证据；第三层把认出的卡放进 加卡后/模式卡/，交给智能体照着做。下表“放在哪一步”对应模板 AGENTS.md 的九步。

模式说明任务怎样组织。卡片上的规则、技能和检查脚本是表达这些要求的配置，运行记录和测试用来检查它们是否真的执行；复杂的状态管理、权限和审批，还需要相应的运行时机制。

## Qoder CN 与 TRAE 的配置对照

每张卡末尾的“Qoder CN 配置”只写这张卡用到的那一种配置。完整对照如下（Qoder CN IDE 1.34.0、TRAE CN 3.4.3，2026-11-04 实测；Qoder CN IDE 1.38.0 于 2026-11-09 复测，位置和写法相同）。

| 配置 | Qoder CN | TRAE |
| --- | --- | --- |
| 规则 | 设置 → 规则 → 添加 → 项目级规则，生成 `.qoder/rules/<名>.md`；类型选“始终生效”（手动引入的要在会话里 @ 规则） | `.trae/rules/<名>.md`，到设置的“规则与记忆”确认生效方式为“始终生效” |
| 技能 | `.qoder/skills/<名>/SKILL.md`，重新加载窗口后在 `/` 列表里确认，用 `/<名>` 点名 | `.trae/skills/<名>/SKILL.md`，在技能列表确认已加载 |
| 子智能体 | `.qoder/agents/<名>.md`，用 `/<名>` 点名 | `.trae/agents/<名>.md`，要先在设置 → Beta 打开“启用 Subagents 目录” |
| Hook | `.qoder/settings.json` 的 `hooks.PreToolUse`；编辑工具名是 `SearchReplace`（matcher 写 `Edit|Write` 能匹配到），脚本以退出码 2 拦截；改完重新加载窗口 | `.trae/hooks.json` 加 `.trae/hooks/` 下的脚本，脚本输出 `permissionDecision`；要信任文件夹，在设置 → Hooks → 项目打开开关并确认安全警示 |
| AGENTS.md | 在对话里明确要求先读，不假设会自动加载 | 设置的“规则”页打开“将 AGENTS.md 包含在上下文中” |

`.lingma/` 下的旧目录 Qoder 同样会读取。用了几张 Hook 卡的组，把各自的条目合并进同一个 `PreToolUse` 数组，不要互相覆盖。
