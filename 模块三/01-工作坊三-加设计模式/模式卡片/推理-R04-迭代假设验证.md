# R04 迭代假设验证

坐标：推理 × 循环　　落地形式：规则

## 是什么

提出假设，为每个假设找能推翻它的证据，排除、修正，直到收敛或到达上限。

## 放在哪一步

第 6 步跑测试：结果对不上时，先排查再改。

## 供修改使用

交给 TRAE：“按这张卡，在项目里创建下面的文件，内容照抄，再按我们组的情况改。”

`.trae/rules/debug.md`

```markdown
# 结果对不上时

测试失败或算出的数和预期不同，不要直接改代码，先排查：
1. 列出至少三个可能的原因，每个原因写一个能推翻它的检查；
2. 逐个执行检查，记下结果：排除 / 保留；
3. 只剩一个原因时再动手改；
4. 最多三轮，仍不能确定就停下，把排查记录交给我。
排查记录写进 notes/debug.md。
```

## 怎么看它起作用了

把 data/结算价.csv 里一个结算价改成不是 5 的整数倍，让它跑测试，看它是否先列原因和检查，而不是直接改脚本或测试。

## 代价

原因明显的问题直接修；没有轮数上限会一直试下去，只找支持的证据也会越走越偏。

## Qoder CN 配置

设置 → 规则 → 添加 → 项目级规则，名称填 `debug`，Qoder 新建 `.qoder/rules/debug.md`。把上面规则文件里第二个 `---` 以下的正文粘贴进去（开头 `---` 之间的几行是 TRAE 的写法，不复制），顶部类型选“始终生效”。新建会话，发通知处理请求，展开回复里的操作记录，确认它读到了这条规则，再按“怎么看它起作用了”检查。

业务资料、输出格式和检查方法与上面 TRAE 的示例相同；两款工具的路径和工具名对照见本目录 README 末尾。
