# 工作坊三：加设计模式

同一个模式可以写在三个地方：AGENTS.md 里的一句话、单独的配置文件、一张模式卡。工作坊分三层，一层看一种写法。三层用同一句请求各跑一遍，比较智能体的做法有什么变化。

| 文件 | 内容 |
| --- | --- |
| [模板/](模板/) | 处理参数类通知的智能体（练习版），原样保留，不直接打开 |
| [改动/](改动/README.md) | 六组的改动，每组一个文件夹：配置文件和一页说明 |
| [模式卡片/](模式卡片/README.md) | 27 个矩阵模式和可观测性，各一张卡 |
| [准备.py](准备.py) | 把 模板/ 复制成三份，放好本组的改动和模式卡 |
| [记录表.md](记录表.md) | 三层各填一部分 |
| [展示.md](展示.md) | 展示提纲 |

## 准备

在这个文件夹里打开终端（访达里右键文件夹，选“新建位于文件夹位置的终端窗口”；Windows 在资源管理器的地址栏输入 cmd 回车）。组名写本组的；用 Qoder 的写 qoder，用 TRAE 的写 trae：

```
python3 准备.py 一组 qoder
```

它建两份副本：`加模式前/` 和模板一样；`加模式后/` 多了本组的改动。第三层再建第三份，见下文。做乱了，删掉那一份，重新运行。

每一份都单独用 IDE 打开，项目根目录就是这一份（AGENTS.md 所在的那一层）。Qoder 打开新文件夹会先弹“建立代码库索引”，选一个才能在会话里输入。TRAE 要在设置的“规则”页打开“将 AGENTS.md 包含在上下文中”。

三层都发同一句请求，每次开新会话：

```
按 AGENTS.md 处理 inbox 里的全部通知，把变更单写到 draft/。
```

有的组还要多做一两步，写在 `改动/<本组>/说明.md` 里，三层都照做。

## 第一层：模式写在 AGENTS.md 里（加模式前/）

1. 读 AGENTS.md。九步里已经有几个模式，比如按固定顺序一步接一步、计算交给 scripts/calc.py。找出两个，写编号和全名。再看本组的问题方向写在九步里的哪一步，还是没写。
2. 跑一遍，按记录表填观察表。
3. 讨论：AGENTS.md 里每一句该放在哪里？留在 AGENTS.md、写进请求、写成进度清单，还是拿出来写成规则、技能、子智能体或 Hook？

## 第二层：模式落成配置文件（加模式后/）

1. 读 `改动/<本组>/` 里的文件，对照 模式卡片/ 认出它们是哪个模式。
2. 按 说明.md 让配置生效，跑一遍，再填一次观察表。
3. 两遍比：差别落在哪个文件、九步里的哪一步。填定位表。

## 第三层：模式写成卡（加卡后/）

1. 建第三份，后面写上第二层认出的卡的编号（一张或两张，空格隔开）：

   ```
   python3 准备.py 一组 qoder 编号 编号
   ```

   `加卡后/` 里有同样的改动，卡放在 `加卡后/模式卡/`。
2. 新会话发下面这段：

   ```
   按 AGENTS.md 处理 inbox 里的全部通知，把变更单写到 draft/。本组的模式卡在 模式卡/ 下，先读卡；卡上的配置已经建好，不要改 .qoder/ 和 .trae/。做完按卡上“怎么看它起作用了”逐条自查，写出每一条的结果和证据。
   ```

3. 和第二层比：照做是不是更稳，有没有自己做卡上的检查，多花了多少时间。

展示按 展示.md，三层各讲一段。

Windows 上把命令里的 python3 换成 python。
