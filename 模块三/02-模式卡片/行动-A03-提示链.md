# A03 提示链

坐标：行动 × 链式　　落地形式：技能

## 是什么

把一个大任务拆成固定的几步，每步有自己的提示和检查，上一步的输出是下一步的输入。

## 放在哪一步

第 1—5 步：处理一份参数调整通知的固定五步。

## 供修改使用

交给 TRAE：“按这张卡，在项目里创建下面的文件，内容照抄，再按我们组的情况改。”

`.trae/skills/notice-pipeline/SKILL.md`

```markdown
---
name: notice-pipeline
description: 处理一份参数调整通知、起草变更单时使用；只查一个参数值、处理节假日通知时不要使用。
---

# 参数通知五步

按顺序做，上一步没通过，不进下一步：
1. 摘要素：合约、参数、新值、起用日期、通知编号。缺一项就停。
2. 查依据：有没有更正通知；原值取自 prod/params.csv。
3. 计算：用 scripts/calc.py 算涨跌停价，贴出命令和输出。
4. 写变更单：draft/变更单-<通知编号>.md，表头 合约 | 参数 | 原值 | 新值 | 起用日期 | 依据。
5. 自查：每行都有依据；数字和第 3 步的输出一致。
```

## 怎么看它起作用了

开一个新任务说“处理第 102 号通知”，看回复里是否提到用了 notice-pipeline、是否按五步走，缺信息时是否停下。

## 代价

步骤会随通知类型变化时，用规划执行；步骤之间不检查，一步错会一路传到变更单。

## Qoder CN 配置

把上面的 `SKILL.md` 放到 `.qoder/skills/notice-pipeline/SKILL.md`，命令面板运行“开发人员: 重新加载窗口”，会话里输入 `/` 确认技能在列表里。先不点名，按“怎么看它起作用了”提问，看调用记录里有没有出现 Skill；没有触发时，再用 `/notice-pipeline` 点名调用。

业务资料、输出格式和检查方法与上面 TRAE 的示例相同；两款工具的路径和工具名对照见本目录 README 末尾。
