# G01 审批门

坐标：治理 × 路由　　落地形式：Hook

## 是什么

按风险和前置条件，把动作分到拒绝、自动放行或人工审批；批完执行的必须是批准的那一版。

## 放在哪一步

第 7—8 步：写生产参数前停下来等人确认。

## 供修改使用

交给 TRAE：“按这张卡，在项目里创建下面的文件，内容照抄，再按我们组的情况改。”

`.trae/hooks.json`

```json
{
  "version": 1,
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "python3 .trae/hooks/approve_prod.py",
            "timeout": 10
          }
        ]
      }
    ]
  }
}
```

`.trae/hooks/approve_prod.py`

```python
import json, re, sys

tool_input = json.load(sys.stdin).get("tool_input", {})
paths = [v.replace("\\", "/") for v in tool_input.values()
         if isinstance(v, str) and "\n" not in v and re.search(r"\.(py|md|csv|json|jsonl)$", v)]

if any(re.search(r"(^|/)prod/", p) for p in paths):
    json.dump({"hookSpecificOutput": {
        "hookEventName": "PreToolUse",
        "permissionDecision": "ask",
        "permissionDecisionReason": "要改生产参数：先看变更单里的原值、新值和依据，再决定是否允许"
    }}, sys.stdout, ensure_ascii=False)
sys.exit(0)
```

已经有 `.trae/hooks.json` 的，只把 `PreToolUse` 数组里的这一条加进去。Windows 上把 python3 改成 python。

## 怎么看它起作用了

让它把变更写入 prod/params.csv，看 TRAE 是否弹出确认；写 draft/ 时不弹。Hook 要先信任文件夹，再在设置 > Hooks > 项目里打开开关。

## 代价

每一步都要确认，人会开始不看就点；确认时看不到原值、新值和依据，确认只是形式。

## Qoder CN 配置

Qoder 的 Hook 写在 `.qoder/settings.json`：`{"hooks": {"PreToolUse": [{"matcher": "Edit|Write", "hooks": [{"type": "command", "command": "python3 .qoder/hooks/approve_prod.py"}]}]}}`。脚本从标准输入读 JSON，目标路径在 `tool_input.file_path`，Qoder 的编辑工具名是 `SearchReplace`。上面 TRAE 脚本输出 `permissionDecision` 的那段不能直接用：把判断条件搬过来，要拦截时向标准错误写原因、以退出码 2 结束，放行时退出码 0。改完重新加载窗口，用一次越界的编辑请求和一次正常的编辑请求各测一遍。Qoder 的 Hook 能不能像 TRAE 那样弹出确认（ask），本次没有实测；实测过的做法是：Hook 以退出码 2 拒绝编辑 prod/，再加一条始终生效的规则，写明“写 prod/ 前，draft/ 里要有对应的变更单，并且用户在本次对话里点名批准第几号”。

业务资料、输出格式和检查方法与上面 TRAE 的示例相同；两款工具的路径和工具名对照见本目录 README 末尾。
