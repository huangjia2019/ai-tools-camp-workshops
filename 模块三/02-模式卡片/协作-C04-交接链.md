# C04 交接链

坐标：协作 × 链式　　落地形式：规则

## 是什么

长流程拆给职责明确的几个智能体，用结构化的交接包传递状态和责任。

## 放在哪一步

第 5—7 步：起草、测试、复核、审批之间交接。

## 供修改使用

交给 TRAE：“按这张卡，在项目里创建下面的文件，内容照抄，再按我们组的情况改。”

`.trae/rules/handoff.md`

```markdown
# 交接单

每完成一棒，在 notes/handoff.md 追加一段，下一棒只读这一段就能开始：
## 第 N 棒：起草 / 测试 / 复核 / 审批
- 通知编号：
- 起用日期：
- 这一棒做了什么：
- 产出文件：
- 结果与依据：
- 没解决的问题：
- 下一棒要做什么：
下一棒不改上一棒的结论；有异议，写进“没解决的问题”。
```

## 怎么看它起作用了

起草完成后开一个新任务，只说“接着做测试这一棒”，看它是否只读 notes/handoff.md 就能开始。

## 代价

交接字段没定义，下一棒只能重新问一遍；谁都能改上一棒的结论，责任就说不清。

## Qoder CN 配置

设置 → 规则 → 添加 → 项目级规则，名称填 `handoff`，Qoder 新建 `.qoder/rules/handoff.md`。把上面规则文件的内容整段粘贴进去，顶部类型选“始终生效”。新建会话，发通知处理请求，展开回复里的操作记录，确认它读到了这条规则，再按“怎么看它起作用了”检查。

业务资料、输出格式和检查方法与上面 TRAE 的示例相同；两款工具的路径和工具名对照见本目录 README 末尾。
