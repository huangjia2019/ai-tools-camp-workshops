# X01 可观测性

坐标：横切工程面，不占矩阵格子　　落地形式：规则

## 是什么

用统一的事件记录、同一个任务编号、版本和外部回执，把运行过程组织成可查询、可追溯的证据链。

## 放在哪一步

每一步：记一行运行记录。

## 供修改使用

交给 TRAE：“按这张卡，在项目里创建下面的文件，内容照抄，再按我们组的情况改。”

`.trae/rules/log.md`

```markdown
# 运行记录

每完成一步，在 logs/run.jsonl 末尾追加一行 JSON，例如：
{"时间": "2026-12-29 09:12", "任务": "N102", "步骤": "计算", "输入": ["data/结算价.csv"], "输出": ["draft/变更单-102.md"], "依据": "第 102 号通知第一条", "结果": "三个合约已计算"}
同一份通知的记录用同一个任务编号。写入 sim/ 或 prod/ 之后，运行 python3 scripts/calc.py verify <文件>，把输出写进“结果”。
记录里不写账号、密码和密钥。
```

## 怎么看它起作用了

处理完一份通知后打开 logs/run.jsonl，按任务编号能看出每一步做了什么、依据是什么。

## 容易做错的地方

只记“做了什么”，不记依据和版本，事后还是说不清；记录里不能写账号、密码和密钥。

## Qoder CN 配置

设置 → 规则 → 添加 → 项目级规则，名称填 `log`，Qoder 新建 `.qoder/rules/log.md`。把上面规则文件的内容整段粘贴进去，顶部类型选“始终生效”。新建会话，发通知处理请求，展开回复里的操作记录，确认它读到了这条规则，再按“怎么看它起作用了”检查。

业务资料、输出格式和检查方法与上面 TRAE 的示例相同；两款工具的路径和工具名对照见本目录 README 末尾。
