# M04 失败日记

坐标：记忆 × 循环　　落地形式：规则

## 是什么

把失败的事实、诊断和验证过的教训分开记，相似任务开始前取回仍然有效的教训。

## 放在哪一步

开始前和出错后：读踩坑记录，确认原因后追加。

## 供修改使用

交给 TRAE：“按这张卡，在项目里创建下面的文件，内容照抄，再按我们组的情况改。”

`.trae/rules/lessons.md`

```markdown
# 踩坑记录

开始处理通知前，先读 notes/lessons.md，列出和这次有关的条目。
出错并确认原因后，在 notes/lessons.md 追加一条：
- 日期：
- 事实：输入是什么，输出错在哪里
- 原因：（已核实 / 待核实）
- 以后怎么做：
- 适用范围：哪类通知、哪个版本的规则
“待核实”的条目只能当提醒，不能当规则用。
```

## 怎么看它起作用了

先让它只看第 102 号通知就起草变更单，再指出套期保值持仓比例没有按更正通知写；它确认原因后应追加一条。开新任务处理同类通知时，看它开始前是否列出这一条。

## 代价

没核实的猜测写成规则，会误导下一次；规则改了，旧条目要删掉。

## Qoder CN 配置

设置 → 规则 → 添加 → 项目级规则，名称填 `lessons`，Qoder 新建 `.qoder/rules/lessons.md`。把上面规则文件的内容整段粘贴进去，顶部类型选“始终生效”。新建会话，发通知处理请求，展开回复里的操作记录，确认它读到了这条规则，再按“怎么看它起作用了”检查。

业务资料、输出格式和检查方法与上面 TRAE 的示例相同；两款工具的路径和工具名对照见本目录 README 末尾。
